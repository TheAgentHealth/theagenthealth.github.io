v0.22.0 publication verification

Release: AgentHealth v0.22.0, published November 9, 2026 as the regular Latest release. Source commit: d7d85027606baad31b83a5614a1c7e0314643bf5. Follow-up inspection: November 13, 2026. The published tag and artifacts were not changed by this documentation update.

Publication and CI evidence

The Release workflow passed its CI gate, validation, release assets, container, OCI packages, npm, PyPI and final publication jobs, including its Docker Hub deployment record. Recovery jobs were skipped because ordinary publication succeeded. The exact-source pre-release CI also passed. This records the workflow results; it does not substitute for independent verification of every signature or platform at follow-up.

Public downloads and registries

All 21 GitHub release assets were downloaded anonymously and their SHA-256 digests checked against the release metadata. Every entry in checksums.txt also matched its downloaded file. The release contains five platform archives, five CycloneDX SBOMs, four DEB/RPM packages, Homebrew/Scoop manifests, Helm chart, Python wheel and source archive, npm tarball and checksum manifest.

PyPI 0.22.0 wheel/source downloads were byte-identical to the release assets. The npm 0.22.0 tarball was byte-identical to its release asset and matched registry SHA-512 integrity. npm's latest tag resolved to 0.22.0.

Anonymous GHCR manifest/config access confirmed Linux AMD64/ARM64 images, version v0.22.0 and the exact source revision. All Helm and binary-bundle layers were downloaded anonymously and matched their digests; the chart layer and bundled release files match the GitHub asset hashes. Docker Hub's public tag API confirmed the recorded digest and both platforms. Direct anonymous Docker Hub manifest retrieval was rate-limited (HTTP 429), so that registry's blobs were not independently downloaded during follow-up.

Runtime checks and verification limits

The published Linux AMD64 archive executed successfully: version reported v0.22.0; conformance test accepted healthy.json and dependency.json with exit 0, and rejected inconsistent.json with inconsistent_status and exit 6. Other platforms were checked through downloadable hashes and pre-release CI, not executed locally during follow-up. Container runtime, installed SDK, DEB/RPM installation and deployed Kubernetes checks were not repeated locally. Cryptographic provenance, SBOM attestations and registry signatures were not independently reverified during this follow-up; checksum equality is not a replacement for signature verification. Use the installation verification instructions.

The packaged SDK READMEs and PyPI description still refer to v0.21.0 although package metadata and runtime version constants are 0.22.0. Current source instructions are corrected separately; existing immutable package bytes retain the older prose. A future release must carry those corrections.

Security follow-up

The November 13 scheduled CI run passed Reference conformance but failed the Go vulnerability scan. It reported GO-2026-6859 in net/http at Go 1.27.3, with Go 1.27.4 identified as the fix. The released Linux AMD64 SBOM records Go 1.27.3. Publication availability does not imply that this later security finding has been resolved. Current source advances CI/release builds and the pinned Docker builder to Go 1.27.4. Publish a new synchronized patch release after validating that source; do not replace v0.22.0 or move its tag.

Phase 24 provides bounded offline result validation and reference behavioral evidence. Certification, independent product interoperability and remaining Phase 26 hardening are outside that baseline.
