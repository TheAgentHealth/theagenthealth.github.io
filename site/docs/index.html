Documentation guide

Start with installation, then choose an adapter and deployment mode. Capability status is generated from status.json. Published release notes describe their tagged versions; source-only improvements require a build containing the change.

Examples are templates requiring your services and credentials. Schema/example validation proves structure, not connectivity or product interoperability. See examples and testing for repeatable local commands and remaining acceptance criteria.

The Python SDK provides typed sync/async CLI access; see its impact review and example.

  • JavaScript / TypeScript SDK — Node ESM wrapper and npm distribution.
  • Phase 16 alignment — earlier/later phase impact review.

Phase 17 implements model/LLM health for OpenAI-compatible and Anthropic APIs. Passive model listings and explicit minimal inference preserve existing health semantics. See the Phase 17 alignment audit for cross-phase impacts.

Phase 18 adds native database health for PostgreSQL, MySQL, Redis and MongoDB. Fixed SQL queries require explicit functional opt-in. See the alignment audit and disposable examples.

Phase 19 implements Qdrant and Pinecone vector-store checks with explicit read-only query opt-in. See the phase alignment audit.
