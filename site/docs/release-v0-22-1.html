AgentHealth v0.22.1

Patch release for the Phase 24 conformance baseline introduced in v0.22.0. CI, release archives and the digest-pinned Docker builder advance from Go 1.27.3 to Go 1.27.4 to address the standard-library finding GO-2026-6859. SDK package descriptions select the matching version, and source documentation records v0.22.0 publication evidence and its verification limits.

Installation and distributions

Publication is pending until the synchronized Release workflow and public verification complete. All implemented formats use v0.22.1: five platform CLI archives, five CycloneDX SBOMs, four DEB/RPM packages, Homebrew/Scoop manifests, Docker images, Helm chart, OCI binary bundle, Python wheel/source archive and npm tarball. Existing v0.22.0 tags and artifacts remain unchanged.

After publication:

docker run --rm ghcr.io/theagenthealth/agenthealth:v0.22.1 version
docker run --rm theagenthealth/agenthealth:v0.22.1 version
pip install agenthealth==0.22.1
npm install @theagenthealth/agenthealth@0.22.1
helm install agenthealth oci://ghcr.io/theagenthealth/charts/agenthealth --version 0.22.1
helm install agenthealth https://github.com/TheAgentHealth/agenthealth/releases/download/v0.22.1/agenthealth-0.22.1.tgz
oras pull ghcr.io/theagenthealth/agenthealth-binaries:v0.22.1

CLI and SDK versions must match. Helm uses chart version 0.22.1, appVersion: v0.22.1 and image ghcr.io/theagenthealth/agenthealth:v0.22.1. The Kubernetes manifests, chart and examples share the immutable source tag. OCI binary retrieval requires an artifact client. Homebrew/Scoop files are manifests; hosted taps/buckets and APT/YUM repositories remain separate work.

Validation and verification

Publication requires fresh CI for the exact source SHA, including mandatory Reference conformance, all five native archive distribution jobs, SDK matrices, Kubernetes 1.31.9/1.33.1 interoperability and the Helm/runtime gate. After publication verify asset checksums and provenance, SBOM attestations, public registry access, SDK byte identity and installed native behavior. Runtime claims must identify the platforms and deployment scenarios actually tested. See distribution and the verification instructions.

Compatibility and limitations

No AHS/AHP v1 fields, adapter interfaces, SDK APIs, health states or health exit codes change. Existing configurations require no migration. Conformance still returns 0 for valid evidence and 6 for invalid evidence or tool failure. The Go minimum remains 1.26; patched build-toolchain pins do not change it.

Offline validation and the reference behavioral catalog do not establish certification, independent product interoperability or a security audit. Native executable signing/notarization and remaining Phase 26 hardening are still outside this release. The Go toolchain update does not alter previously published v0.22.0 binaries.
